# Симулятор футбольного букмекера (MVP)

Образовательное веб-приложение в стиле мобильной игры: пользователь делает ставки
на виртуальные деньги и на собственной статистике (ROI, винрейт, история ставок)
убеждается, что встроенная в коэффициенты маржа букмекера на длинной дистанции
гарантированно уводит баланс в минус.

Технологии: **Node.js + Express**, **PostgreSQL**, фронтенд — чистые **HTML/CSS/JS**
(ES-модули, без сборщика), отрисованный как мобильное SPA с нижней навигацией.

## Файловая структура

```

    utils/

    routes/
      auth.routes.js            # register / login / logout / me
```

## Как устроена регистрация и безопасность

Регистрация двухшаговая:

1. **Шаг 1 — email + пароль.** Пользователь вводит email (проверяется regex'ом)
   и пароль (от 6 символов). Никнейм на этом шаге не запрашивается — в БД
   `users.username` остаётся `NULL`. Пароль **никогда** не сохраняется в открытом
   виде — хэшируется через `bcrypt` с 12 раундами соли (`auth.routes.js`).
   При успешной вставке строки `balance` автоматически становится `1000.00` —
   это `DEFAULT` в схеме `users.balance`, а не логика в коде (нельзя забыть/обойти).
   Сервер сразу выдаёт JWT-сессию (см. ниже), чтобы шаг 2 проходил уже "залогиненным".
2. **Шаг 2 — никнейм.** `POST /api/auth/set-username` можно вызвать только пока
   `username IS NULL` — задать его повторно после этого нельзя, это постоянный
   публичный идентификатор для поиска в друзьях. Фронт (`main.js`) при каждой
   загрузке приложения проверяет `user.username`: если он не задан (например,
   вкладку закрыли между шагами регистрации), пользователя принудительно
   возвращают на экран выбора ника, минуя основное приложение.
3. **Вход** — по email и паролю (`POST /api/auth/login`). Сообщение об ошибке
   одинаковое и для "нет такого email", и для "неверный пароль" — чтобы не
   подсказывать атакующему, какие адреса зарегистрированы.
4. Сервер подписывает JWT (`jsonwebtoken`, секрет `JWT_SECRET`) и кладёт его в
   **httpOnly cookie** — `document.cookie` из браузерного JS его не видит, это
   защита от кражи токена через XSS. Дополнительно `sameSite: lax` снижает риск CSRF.
5. Каждый защищённый роут проходит через `middleware/auth.js`, который проверяет
   подпись и достаёт `userId`.

## Аватарки

Два независимых источника, взаимоисключающих друг друга (`avatar_url` в приоритете):

- **Готовые иконки** — 6 эмодзи, выбор через `PATCH /api/profile/avatar { avatar_id }`.
  Сбрасывает `avatar_url` в `NULL`.
- **Своя фотография из медиатеки** — `POST /api/profile/avatar/upload` (multipart,
  поле `avatar`), обрабатывается `multer` (лимит 3 МБ, только JPEG/PNG/WEBP/GIF).
  Файл сохраняется в `backend/uploads/avatars/`, раздаётся статикой по `/uploads/*`,
  путь пишется в `users.avatar_url`. Старый загруженный файл удаляется при замене.
  На фронте `utils.js#avatarHtml()` рендерит либо `<img>`, либо эмодзи; если файл
  битый/удалён — делегированный обработчик `error` в `main.js` подменяет его на
  эмодзи-заглушку.

## Схема PostgreSQL (см. `backend/src/db/schema.sql`)

- **users** — `id, email (unique), username (unique, nullable до шага 2 регистрации),
  password_hash, balance, avatar_id, avatar_url, last_click_at, last_ad_watch_at`.
- **leagues** — справочник турниров (`key`, `name`, `api_sport_key` для The Odds API, `logo_url`).
- **matches** — кэш коэффициентов: `odds_home/draw/away`, `odds_updated_at`, `is_frozen`,
  `status`, `result`. `external_id` с уникальным индексом нужен для upsert из реального API.
- **bets** — ставка фиксирует `odds_at_bet` (кэф на момент ставки, а не текущий),
  `league_id` продублирован из матча ради быстрой статистики по лиге без лишнего JOIN.
- **friend_requests** — связь "многие ко многим" между `users` реализована ОДНОЙ
  таблицей направленных заявок со статусом (`pending/accepted/declined`), а не
  отдельными таблицами "друзья" и "заявки". Это стандартный паттерн: дружба —
  это просто заявка в статусе `accepted`, где неважно, кто был отправителем.
- **team_logos** — кэш эмблем команд по названию (`team_name` PK → `logo_url`),
  общий для всех лиг/матчей с этой командой, заполняется один раз при сидировании.

Применяются миграцией `npm run migrate` (идемпотентна благодаря `IF NOT EXISTS`
и безопасным `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` для уже существующих БД).

## Логотипы лиг и команд

Реальные эмблемы подтягиваются из бесплатного публичного [TheSportsDB](https://www.thesportsdb.com/)
(`logoService.js`, тестовый ключ `3`, действует ограничение по трафику для интенсивного
использования — но нам достаточно): лига — по стабильному числовому ID
(`lookupleague.php?id=...`, ID прописаны в `mockLeagues.json` как `thesportsdb_league_id`),
команда — поиском по названию (`searchteams.php?t=...`) с кэшированием результата
в таблицу `team_logos` навсегда, так что повторные `npm run seed` не дёргают API заново.
Если логотип не нашёлся или картинка не загрузилась в браузере — фронт показывает
кружок с инициалами команды вместо неё (см. `teamBadgeHtml()` в `utils.js`).

Так как это чужие товарные знаки, эмблемы уместны для локального
некоммерческого MVP, но не стоит их использовать в публично раздаваемом продукте
без разрешения правообладателей.

## Логика коэффициентов и "неизбежного проигрыша"

`oddsService.generateMockOdds()` генерирует кэфы через "истинные" вероятности
исходов, применяя к ним маржу букмекера 6-10% (`margin`). Из-за этого сумма
`1/кэф` по всем трём исходам всегда **больше 1**.

`settlementService.drawResult()` разыгрывает реальный исход матча, нормализуя
эти же обратные коэффициенты в вероятности, суммирующиеся ровно к 1. Математически
это означает, что мат.ожидание любой ставки равно `сумма / margin < сумма` —
то есть **строго отрицательно** независимо от выбранного исхода. Именно это
на дистанции и "убивает" ROI игрока во вкладке "Профиль", в точности как в
реальном бетинге.

`oddsCron.js` каждые 15 минут вызывает `reconcileOdds()`, которая обновляет
кэф не чаще раза в час, если до матча ≤6 часов, и не чаще раза в 12 часов,
если матч ещё далеко; в момент старта матча коэффициент замораживается
(`is_frozen = true`) и больше не трогается. Каждые 5 минут `simulateAndSettleFinishedMatches()`
"доигрывает" матчи, время которых прошло, и рассчитывает ставки.

## Мок-данные vs реальный The Odds API

`USE_MOCK_ODDS=true` (по умолчанию в `.env.example`) — коэффициенты полностью
генерируются локально (`mock/mockLeagues.json` + `generateMockOdds`), лимиты
API не тратятся, всё можно тестировать офлайн.

Чтобы подключить реальный [The Odds API](https://the-odds-api.com/):
1. Получите бесплатный `ODDS_API_KEY`.
2. В `.env` поставьте `USE_MOCK_ODDS=false` и впишите ключ.
3. `fetchRealOddsForLeague()` в `oddsService.js` сама подтянет `h2h`-рынок
   по `api_sport_key` каждой лиги и сделает upsert в `matches` по `external_id`.

## Локальный запуск

Требования: **Node.js ≥ 18** (нужен глобальный `fetch`), **PostgreSQL ≥ 13**.

```bash
# 1. Создать базу данных
createdb bookmaker_sim
# (или через psql: CREATE DATABASE bookmaker_sim;)

# 2. Настроить бэкенд
cd backend
cp .env.example .env
# откройте .env и при необходимости поправьте DATABASE_URL / JWT_SECRET

npm install
npm run migrate   # создаёт/обновляет таблицы
npm run seed       # заполняет лиги, тестовые матчи (мок) и подтягивает логотипы с TheSportsDB

npm run dev         # или npm start — поднимет http://localhost:4000
```

`npm run seed` обращается к TheSportsDB за эмблемами — нужен интернет; если его
нет или API недоступен, сидирование всё равно завершится успешно, просто без
логотипов (фронт покажет кружки с инициалами вместо них).

Фронтенд отдельно поднимать не нужно — Express в `src/index.js` раздаёт
`frontend/public` как статику и является SPA-фолбэком, так что API и
интерфейс живут на одном порту без CORS-костылей.

Откройте **http://localhost:4000** — попадёте на экран регистрации.
Зарегистрируйтесь по email и паролю, придумайте никнейм на втором шаге,
получите 1000 ₽ и переходите к ставкам.

Чтобы увидеть, как матчи "доигрываются" и ставки рассчитываются
автоматически — подождите несколько минут после старта сервера
(в сиде часть матчей стартует уже через ~1 час, но крон-джоб настроен
достаточно часто, чтобы вы увидели весь цикл, не меняя код; при желании
можно временно уменьшить `MATCH_DURATION_MINUTES` в `settlementService.js`
и сдвинуть `commence_time` в `seed.js`, чтобы протестировать расчёт мгновенно).
